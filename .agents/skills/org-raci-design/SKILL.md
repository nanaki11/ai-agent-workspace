# 組織・役割分担の設計

## 1. 組織形態
| 形態 | 向いている場面 | 弱み |
|---|---|---|
| 機能別 | 単一事業、効率重視 | 部門の壁、意思決定が上に集中する |
| 事業部制 | 複数事業、市場ごとに素早く対応 | 機能の重複、事業部間の連携が弱い |
| マトリクス | 製品×地域など2軸の両立 | 指揮命令が二重になり、責任が曖昧になる |
| CoE・シェアード | 専門機能の集約（IT、経理、人事） | 現場から遠くなる |

- 組織は戦略に従う：どの戦略・業務を実現するための組織かを先に書く
- 案を2〜3個作り、評価軸（戦略との適合、意思決定の速さ、コスト、移行の難しさ）で比べる

## 2. RACI
| 記号 | 意味 | ルール |
|---|---|---|
| R（Responsible） | 実際に作業する | 1つ以上 |
| A（Accountable） | 最終責任を持ち、承認する | 必ず1つだけ |
| C（Consulted） | 事前に相談される | 必要最小限 |
| I（Informed） | 結果を知らされる | |

表の形：行＝業務（bpm-process-mapping の L3）、列＝部署・役割

チェック：
- [ ] すべての行に A がちょうど1つある
- [ ] R のない行がない
- [ ] 1つの列に A や R が集中しすぎていない（その役割がボトルネックになる）
- [ ] C が多すぎる行がない（意思決定が遅くなる）

## 3. 業務分掌
部署ごとに、目的・担当業務・持っている権限・他部署とのやり取りを書く。RACI の R と A が業務分掌と矛盾しないようにする。

## 4. 決裁権限表
| 決裁事項 | 金額・条件 | 起案 | 審査 | 決裁 | 報告 |
|---|---|---|---|---|---|

- 金額の区切りで決裁者を変える（例：100万円未満＝部長、1億円未満＝役員、それ以上＝取締役会）
- 承認の段階は少なくする（目安は3段階以内）

## 出力
- 組織案の比較表と推奨案
- 組織図（drawio-diagram）
- RACI表・決裁権限表（xlsx）
