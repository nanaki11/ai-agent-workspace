# 開発の共通ルール

すべてのプロジェクトで守る。プロジェクト側の CLAUDE.md（Codex では AGENTS.md）に具体的な手順（コマンド、保存先）があれば、それに従う。

## 出力

- ユーザーへの出力はすべて日本語で書く（最終回答だけでなく、作業途中の短い報告も含む）。
- コマンド、ファイル名、識別子、エラーメッセージの引用はそのままでよい。

## フォルダ構成

新しいプロジェクトはこの構成で作る。既存のプロジェクトで構成が違う場合は、勝手に移さずユーザーに確認する。

```text
<プロジェクト>/
├─ README.md              概要、ローカルでの起動方法、デプロイ方法
├─ CLAUDE.md              このプロジェクトだけの手順（任意）
├─ （アプリのコード）       言語やフレームワークの慣習に従う
├─ docs/                  設計書
│  ├─ README.md           設計書の目次と、それぞれの最終更新日
│  ├─ architecture.md     全体の構成（構成図 .drawio も同じ場所に置く）
│  ├─ design/             機能ごとの設計（画面、API、データ、バッチ）
│  ├─ infra/              インフラの設計
│  ├─ ops/                運用手順書（runbook）、ログの調べ方
│  ├─ adr/                重要な判断の記録（NNNN-<タイトル>.md）
│  └─ CHANGELOG.md        いつ・何を変えたか（直した設計書の箇所も書く）
├─ tests/
│  ├─ unit/               単体テストのコード
│  ├─ integration/        結合テスト・クラウドでの確認
│  ├─ run_tests.py        テストを実行して結果を記録するスクリプト
│  └─ reports/            テスト結果
│     ├─ README.md        結果の一覧（日時、種類、判定、何の変更の後か）
│     ├─ unit-test-cases.md  最新の単体テストケース一覧
│     ├─ unit/            YYYYMMDD-HHMMSS-unit.md / .xml
│     ├─ integration/     YYYYMMDD-HHMMSS-<対象>.md
│     ├─ manual/          YYYYMMDD-HHMMSS-<変更内容>.md（ローカルでの手動確認）
│     └─ evidence/        画面キャプチャなどの証跡
└─ deploy/                デプロイ用スクリプトと環境ごとの設定（config.<環境>）
   └─ history.md          デプロイ履歴
```

- 記録ファイルの名前は `YYYYMMDD-HHMMSS-` で始め、名前順で時系列に並ぶようにする。
- 記録を追加したら、`tests/reports/README.md` の一覧にも 1 行追加する。

## 単体テスト

- アプリを実装・変更したら、単体テストを実行し、結果を `tests/reports/unit/` に記録する（画面に出すだけで終わらせない）。
- 記録にはテストケースと結果（合格・不合格、件数、実行日時、何を実装した後か）を含める。
- プロジェクトにテスト実行・記録用のスクリプト（`tests/run_tests.py` など）があればそれを使う。
- 報告では、記録したファイルのパスと判定を伝える。

## 設計書

- アプリを更新するたびに、`docs/` の設計書を最新の実装に合わせて更新する。
- 更新したら `docs/CHANGELOG.md` に変更内容を、`docs/README.md` に最終更新日を書く。
- 設計書がどこにあるか分からない場合は、探したうえで、なければユーザーに確認する。
- 報告では、更新した設計書と変更箇所を伝える。

## デプロイ

- アプリを改修したら、次の順で進める。
  1. 単体テストを実行して記録する（`tests/reports/unit/`）
  2. 設計書を最新化する（`docs/`）
  3. ローカルで起動し、変更箇所を手動で確認して記録する（`tests/reports/manual/`。確認した操作、期待した結果、実際の結果）
  4. ユーザーの了承を得てからデプロイする
  5. `deploy/history.md` に日時、環境、バージョン、手順 1 と 3 の記録へのリンクを書く

- ローカルで起動・確認できていない状態ではデプロイしない。
