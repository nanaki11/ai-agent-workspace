# 定量分析

## 実行契約
作業前に [実行・品質規約](references/consulting-delivery-standard.md) を読む。単独利用時も同じ規約を適用し、作業モードに応じて記録と検証を絞る。


## 共通ルール
- 前提（インプット値）・計算式・結果を分けて書く。前提には出典を付けるか「仮定」と明記する
- 単位と桁を必ず書く（百万円、千人、%、年）
- 計算はスプレッドシートか Python で行う。暗算の数値は出さない
- 結果は幅（悲観／標準／楽観）で示す

## 1. フェルミ推定・市場規模
- 分解の型：人口×対象率×利用率×頻度×単価／事業所数×導入率×単価／既存市場×代替率
- TAM（市場全体）→ SAM（自社が狙える範囲）→ SOM（現実的に取れる規模）の順で示す
- トップダウンとボトムアップの両方で出す。差が大きいときは理由を書く

## 2. 効果額試算（業務改善・IT投資）
| 効果の種類 | 計算式の例 |
|---|---|
| 工数削減 | 対象業務時間×削減率×人件費単価×人数 |
| コスト削減 | 現行コスト − 将来コスト |
| 売上増加 | 客数増×単価、CVR改善×流入数×単価 |
| リスク低減 | 発生確率×損失額の減少分 |

- 「浮く時間」と「実際に減るコスト」は分けて書く（人員の再配置をしなければコストは減らない）

## 3. 投資評価
- NPV ＝ Σ CF_t ／(1+r)^t − 初期投資。割引率は前提として明記する（例：WACC 5〜8%）
- IRR と回収期間（単純／割引後）もあわせて出す
- TCO ＝ 初期費用 ＋ 運用費×年数 ＋ 更新費 ＋ 撤退・移行費（原則5年）

## 4. 感度分析
- 結果を大きく左右する変数を3〜5個選び、±10〜30%動かした結果を表にする（トルネード図の元データ）
- 損益分岐点になる変数の値を示す

## 5. 評価マトリクス（選択肢の比較）
- 評価軸3〜6個、重みの合計100%、点数の基準（1／3／5点の定義）を採点の前に決める
- 重み付き合計とは別に「必須条件（満たさなければ不採用）」をチェックする
- 重みを変えても順位が変わらないか確認する

## 出力フォーマット
```
## 結論（数値と幅）
## 前提一覧
| 変数 | 値 | 単位 | 根拠／出典 |
## 計算ロジック（式）
## 結果（悲観／標準／楽観）
## 感度分析
## 留意点・限界
```
- 計算に使ったスプレッドシートやスクリプトはファイルとして残し、成果物と一緒に渡す

## 実務での追加検証
- 入力表に値・単位・期間・通貨・税込税抜・根拠Eまたは仮定Aを付ける。欠損をゼロと扱わない。
- 複数施策の効果、工数削減とコスト削減、売上と利益を二重計上しない。削減時間の再配置だけでは現金支出削減としない。
- ベースケースと増分CFを分け、移行・並行稼働・撤退費、運転資金を必要に応じて含める。NPVの期間と割引率の単位を一致させる。IRRが存在しない・複数ある場合は明示する。
- 感度幅は根拠を付ける。相関する変数を同時に楽観化しない。損益分岐と推奨逆転条件を示す。
- 合計・内訳・境界値・ゼロ除算・順位の頑健性を再計算する。実行できなかった計算を検証済みと書かない。
