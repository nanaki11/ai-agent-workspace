# ロジカルシンキング／仮説思考

## 目的
いきなり答えを出さない。「何に答えるべきか（イシュー）」を決め、MECEに分解し、仮説と検証方法までを1つの構造として示す。

## 手順
1. **問いを定義する**
   - 依頼を「〇〇すべきか？」「どうすれば〇〇できるか？」の形の1文にする
   - 前提・制約・スコープ外・意思決定者・期限を書く
   - 曖昧な語（「効率化」「DX」「強化」など）は定義を書く
   - 問いが曖昧なまま進めない。不明点はユーザーに確認する
2. **イシューツリーに分解する**
   - 2〜3階層、各階層3〜5個
   - 分解の切り口を必ず書く（例：売上＝客数×客単価、プロセス順、内部／外部、短期／中長期）
   - MECEチェック：漏れ（他にないか）、ダブり（同じものが2つの枝に入っていないか）
3. **ツリーの種類を使い分ける**

   | 種類 | 問い | 使う場面 |
   |---|---|---|
   | What | 何で構成されるか | 全体像・要素の把握 |
   | Why | なぜ起きているか | 原因分析（真因の特定） |
   | How | どう実現するか | 打ち手の洗い出し |

4. **仮説を立てる**
   - 末端の論点ごとに「現時点の答え」を1文で言い切る（情報が不完全でもよい）
   - 確度（高／中／低）と、その根拠を書く
5. **検証計画を作る**
   - 仮説ごとに「どのデータ・分析で、何が分かれば正しいと言えるか」を書く
   - 優先順位：インパクト大×不確実性大の論点から検証する
6. **So What／Why So で確認する**
   - 下から上：事実の束 →「結局どういうことか」（So What）
   - 上から下：主張 →「その根拠は何か」（Why So）。根拠のない主張を残さない

## 出力フォーマット
```
## 問い（メインイシュー）
<1文>
前提／制約／スコープ外：…
用語の定義：…

## イシューツリー
- 論点1：…（切り口：…）
  - 1-1 … → 仮説：… ［確度：中／根拠：…］ → 検証方法：…
  - 1-2 …
- 論点2：…

## 優先して検証する論点
1. …（理由：インパクト／不確実性）
```

## 禁止事項
- 切り口のない羅列。「その他」に逃げない（使うなら全体の1割以下）
- 事実・解釈・意見を混ぜる（「事実：」「解釈：」で書き分ける）
- 仮説を「〜を検討する」「〜が重要」で終える（「〜すべき」「〜が原因である」と言い切る）
