# 業務可視化（BPM）

## 実行契約
作業前に [実行・品質規約](references/consulting-delivery-standard.md) を読む。単独利用時も同じ規約を適用し、作業モードに応じて記録と検証を絞る。


## 1. 業務を階層で棚卸しする（業務機能構成表／DMM）
| 階層 | 粒度 | 例 |
|---|---|---|
| L1 業務領域 | 部門レベルの大きな機能 | 販売 |
| L2 業務 | 一連の目的をもつまとまり | 受注 |
| L3 業務プロセス | フロー図1枚の単位 | 受注登録、与信チェック |
| L4 作業 | 担当者の1つの操作 | 注文書をシステムに入力する |

- 同じ階層の粒度をそろえる。L3 は「動詞＋目的語」で書く
- 業務一覧（Excel）の列：ID（例 SL-01-03）／L1／L2／L3／担当部署／使うシステム／頻度／件数（月）／1件あたりの時間／課題メモ

## 2. ヒアリングで聞くこと（L3ごと）
- きっかけ（何が来たら始まるか）と終わり（何ができたら終わるか）
- インプット（帳票・データ）とアウトプット
- 担当（部署・役割）と、承認する人
- 使うシステム、Excel、紙
- 頻度・件数・時間、繁忙期
- 例外処理（差し戻し、エラー、特急対応）
- 困っていること、手戻り、二重入力

## 3. 業務フローの書き方（スイムレーン）
- レーンは部署・役割・システム。社外（顧客、取引先）は一番上のレーン、システムは一番下のレーン
- 時間は左から右に流す
- 使う記号はこれだけにする（drawio-diagram のスタイル辞書を使う）

  | 記号 | 意味 | 形 |
  |---|---|---|
  | 開始・終了 | きっかけ・完了 | 円 |
  | 作業 | 人やシステムの処理 | 角丸の箱 |
  | 分岐 | 判断 | ひし形（出る線に「OK」「NG」などの条件ラベル） |
  | 帳票・データ | 書類、ファイル | 書類の形 |
  | 外部・他プロセス | 他のフローへの接続 | 点線の箱 |

- 作業名は「動詞＋目的語」（例：「受注内容を確認する」）
- 1枚の作業は15〜25個まで。それ以上なら L3 を分割する
- 例外処理は、主な流れを壊さない範囲で書く。複雑なら別のフローにする
- システムへの入力・参照は、作業からシステムレーンへ点線でつなぐ
- 課題のある作業には赤い注記（番号付き）を付け、課題一覧と番号を対応させる

## 4. 業務記述書（フロー1枚に1つ）
| 項目 | 内容 |
|---|---|
| プロセスID／名称 | |
| 目的 | |
| 開始条件／終了条件 | |
| 関係者 | |
| 作業手順 | 番号はフロー上の作業と対応させる |
| 業務ルール | 判断基準、締め時刻、承認権限 |
| 使うシステム・帳票 | |
| 業務量 | 件数、時間 |
| 課題 | 番号はフロー上の注記と対応させる |

## 5. 成果物
- 業務一覧（xlsx）
- 業務フロー（.drawio。L3ごとに1ページ。PNGも書き出す）
- 業務記述書（md または docx）
- 課題一覧（process-redesign に引き継ぐ）

## チェック
- [ ] 業務一覧、フロー、記述書の ID と名称が一致している
- [ ] すべての分岐に条件ラベルがある
- [ ] 開始と終了がある。行き止まりの作業がない
- [ ] レーンに担当のいない作業がない

## 実務での追加検証
- ヒアリングの発言と観察証拠を分け、部門・繁閑・例外のサンプル偏りを記録する。
- 実作業と待ち時間、通常と例外を区別し、フロー・業務記述・業務量のIDを照合する。
- 簡易スイムレーンを厳密なBPMN準拠と称さない。BPMN指定時はイベント・ゲートウェイ・メッセージとシーケンスの意味を検証する。
