# 成果物レビュー

## 実行契約
作業前に [実行・品質規約](references/consulting-delivery-standard.md) を読む。単独利用時も同じ規約を適用し、作業モードに応じて記録と検証を絞る。


## 観点（上ほど重要）
1. **問いに答えているか**：依頼された問いへの答えが冒頭にあるか
2. **ロジック**：So What／Why So が通るか。根拠のない主張、論理の飛躍、因果と相関の混同がないか
3. **数値**：合計と内訳が一致するか。単位・桁・年がそろっているか。前提が書かれ、計算を再現できるか
4. **出典**：数値・事実に出典があるか。情報の更新頻度・調査目的に対して古い情報を明示しているか
5. **実行可能性**：打ち手に責任者・期限・必要なリソースがあるか
6. **図と一覧の整合**：構成図と一覧表（システム一覧、IF一覧など）の要素が一致するか
7. **表現**：用語の統一（表記ゆれ）、専門用語の説明、1文60字程度
8. **リスク**：機密情報・個人情報、断定しすぎ、他社を不当に貶める表現がないか

## 進め方
- 指摘には重要度を付ける（高＝結論が変わる／中＝説得力が落ちる／低＝体裁）
- 指摘だけでなく修正案も出す
- 重要度「高」が1件でもあれば判定は「要修正」

## 出力
```
## 判定：提出可／要修正／未検証
## 指摘一覧
| # | 重要度 | 箇所 | 指摘 | 修正案 |
## 良い点（変えずに残す点）
```

## 実務での追加検証
- 同梱の実行・品質規約の品質ゲートで、対象版を「提出可／要修正／未検証」と判定する。「OK」は提出可に対応させる。
- 高＝結論・金額・実行可否への重大影響、中＝根拠や説得力の不足、低＝体裁。高の未解決が1件でもあれば要修正とする。必須検証が未実施なら提出可にしない。
- 主張と出典の該当箇所を照合する。出典の有無だけで合格にしない。前提・要件・図・効果・決議事項の対応を追う。
- 指摘表に修正状態と再確認結果を加える。旧社名、期間ずれ、単位誤りなどは全件へ横展開する。
- 独立レビューの実施有無と残る制約を記載する。法務・税務の判断は専門家に確認が必要な箇所を具体化する。
