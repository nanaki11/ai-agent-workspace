# 進捗把握・報告

## 入力（ユーザーから受け取る）
- スケジュール・タスク一覧（計画と実績の日付・工数・進捗率）
- 工数・コストの実績
- 課題管理表・リスク管理表（risk-issue-management）
- 品質データ（quality-management）
- WBS やスケジュールは作らない。PM や既存ツールのデータを受け取って分析する。データが足りなければ、何が足りないかを伝える

## 1. 進捗の数値化（EVM）
| 指標 | 意味 | 計算 |
|---|---|---|
| PV | 今日までに終わっている予定だった作業の価値 | 計画工数（または予算）の累計 |
| EV | 実際に終わった作業の価値 | 各タスクの計画工数 × 進捗率 の合計 |
| AC | 実際にかかった工数・コスト | 実績の累計 |
| SV ／ SPI | スケジュールの差・効率 | EV − PV ／ EV ÷ PV |
| CV ／ CPI | コストの差・効率 | EV − AC ／ EV ÷ AC |
| EAC | 完了時のコストの見込み | BAC ÷ CPI（今の効率が続く場合） |
| 完了時期の見込み | | 残りの作業 ÷（EV の増え方の平均） |

- 進捗率は自己申告だと甘くなる。0／50／100％ ルール（未着手0、着手50、完了100）など、客観的な決め方を勧める

## 2. RAG評価
| 観点 | 緑 | 黄 | 赤 |
|---|---|---|---|
| スケジュール | SPI ≥ 0.95 | 0.85〜0.95 | < 0.85 またはマイルストーンが遅れる |
| コスト | CPI ≥ 0.95 | 0.85〜0.95 | < 0.85 または予算超過の見込み |
| 品質 | 指標が基準の範囲内 | 一部が基準外 | 主要な指標が基準外、または収束しない |
| 課題 | 期限切れなし | 期限切れがある | 重要な課題が期限切れ、または意思決定待ちで止まっている |
| リスク | 高リスクに対策がある | 対策が遅れている | 高リスクが顕在化しそう |
| 体制 | 要員が計画どおり | 一部が欠けている | キーマンが不在、または離任 |

- 閾値はプロジェクトの開始時に合意したものを使う。上の表は初期値
- 総合評価は一番悪い観点に合わせる（赤が1つでもあれば総合も赤）

## 3. 週次・月次報告書
```
## 総合評価：🟢／🟡／🔴（前回：🟢）
## サマリー（3行。悪いことから書く）
## 観点別の状況
| 観点 | 評価 | 状況 | 対応 |
## 主要マイルストーン
| マイルストーン | 計画日 | 見込み日 | 状況 |
## 進捗（EVM）
## 重要な課題・リスク（上位5件）
## 意思決定・支援をお願いしたい事項
## 来週（来月）の予定
```

## 4. ステアリングコミッティ資料
- 最初のページに「決めていただきたいこと」を書く（選択肢、推奨、決めないとどうなるか、期限）
- 次に総合状況（RAG）と、前回からの変化
- 詳細は付録に回す
- storyline-builder で骨子を作り、consulting-pptx-skill でスライドにする

## 5. 健全性診断（遅れているプロジェクト・炎上しているプロジェクト）
次の10観点で、それぞれ 良／注意／危険 を付け、根拠を書く。
1. 目的・スコープが明確で、合意されているか
2. 計画が現実的か（見積の根拠、バッファ）
3. 要件が固まっているか（変更の件数と傾向）
4. 体制とスキルが足りているか、キーマンに依存していないか
5. 意思決定が速いか（決定待ちの件数と日数）
6. 品質（バグの傾向、レビュー指摘の傾向）
7. ベンダーとの関係・契約
8. 課題が溜まっていないか（件数の推移、平均の滞留日数）
9. リスク管理が機能しているか
10. チームの状態（残業時間、離脱）

立て直し案は選択肢として並べ、それぞれの効果・副作用・費用を書く。
- スコープを減らす／リリースを分ける／期限を延ばす／要員を増やす（遅れているプロジェクトへの増員はさらに遅れることがある。立ち上がりの期間も見込む）／体制や進め方を変える
