# EA設計

## 原則
- 業務から考える。技術ありきで考えない（ビジネス層 → データ層・アプリケーション層 → テクノロジー層の順）
- 一覧表（Excel）を正とし、図は一覧表から作る。図と一覧表の要素を必ず一致させる
- As-Is と To-Be は同じ記法・同じ配置で描き、差分が一目で分かるようにする
- 重要な判断は ADR に残す（tech-selection）

## 手順
### 1. スコープとアーキテクチャ原則
- 対象（全社か、特定の事業・業務か）、期間（何年後の To-Be か）
- アーキテクチャ原則を5〜10個。1つずつ「名称／内容／理由／影響」を書く
  - 例：クラウドファースト／SoR（記録のシステム）と SoE（顧客接点のシステム）を分ける／マスタは1か所で管理する／システム間の連携は API を基本にする／パッケージは標準機能のまま使う

### 2. ビジネスアーキテクチャ（BA）
- ケイパビリティマップ：業務機能を L1〜L2 で整理する（bpm-process-mapping の業務一覧を使う）
- 戦略上重要なケイパビリティに印を付ける（差別化領域か、標準化領域か）

### 3. アプリケーションアーキテクチャ（AA）
- アプリケーション一覧（xlsx）

  | 列 | 内容 |
  |---|---|
  | ID／名称 | APP-001 など |
  | 対応する業務機能 | ケイパビリティマップの ID |
  | 種別 | パッケージ／SaaS／独自開発 |
  | 利用部門・ユーザー数 | |
  | 技術 | 言語、DB、基盤 |
  | 保守期限 | OS・ミドルウェア・製品のサポート終了日 |
  | 年間コスト | ライセンス、保守、運用 |
  | 評価 | 業務適合度（1〜5）、技術健全性（1〜5） |

- ケイパビリティ×アプリのマッピング：同じ機能を持つアプリの重複と、システムがない空白を見つける
- TIME評価（業務適合度×技術健全性）

  | | 技術健全性：低 | 技術健全性：高 |
  |---|---|---|
  | 業務適合度：高 | Migrate（基盤を移行する） | Invest（投資して伸ばす） |
  | 業務適合度：低 | Eliminate（廃止・統合する） | Tolerate（現状のまま使う） |

### 4. データアーキテクチャ（DA）
- 主要なデータエンティティ（顧客、商品、取引先、受注、在庫、従業員など）の一覧と定義
- CRUDマトリクス（行＝エンティティ、列＝アプリ。C＝作成、R＝参照、U＝更新、D＝削除）
  - C が複数のアプリにあるエンティティは、データが二重管理されている疑いがある
- マスタの正（どのシステムが正しい値を持つか）を決める
- データフロー図：発生源 → 連携 → 蓄積 → 活用（DWH、BI、AI）

### 5. テクノロジーアーキテクチャ（TA）
- 基盤（オンプレミス／IaaS／PaaS／SaaS）、ネットワーク、認証基盤（ID管理・SSO）、連携基盤（API ゲートウェイ、iPaaS、ETL、メッセージキュー）、運用監視、バックアップ、セキュリティ
- 標準技術一覧：分野ごとに「標準／許容／非推奨」を決める

### 6. インターフェース一覧
| IF-ID | 送信元 | 送信先 | データ | 方式（API／ファイル／DB連携／メッセージ） | 頻度・タイミング | 件数 | 備考 |
|---|---|---|---|---|---|---|---|

### 7. To-Be とギャップ
- As-Is と To-Be の差分：新規／改修／廃止／統合
- 移行ロードマップ：フェーズ分け、システム間の依存関係（「Aを入れ替える前にマスタ統合が必要」など）、並行稼働の期間
- 実施の判断には quantitative-analysis で TCO と効果を出す

## 図の体系（drawio-diagram で作る。1つの .drawio にページを分けて入れる）
| ページ | 読み手 | 内容 |
|---|---|---|
| L0 全体像 | 経営層 | 4層を1枚で。アプリは10〜15個にまとめる |
| ケイパビリティマップ | 経営層・業務部門 | 業務機能の箱を並べ、重要度とシステム化の状況で色分けする |
| システム全体構成図（As-Is／To-Be） | IT部門 | 層ごとのレーンにアプリを置き、連携を線で結ぶ。状態（新規・改修・廃止）を線の種類で表す |
| データフロー図 | IT部門・データ担当 | 主要エンティティの流れ |
| C4 Context／Container | 開発チーム | 対象システムの外部との境界と内部の構成 |
| インフラ構成図 | 基盤担当 | クラウド／オンプレのネットワークと配置 |

- システム全体構成図は `${CLAUDE_PLUGIN_ROOT}/skills/drawio-diagram/examples/sample-system-overview.drawio` を雛形にする
- 線のラベルには IF-ID かデータ名を書き、インターフェース一覧と対応させる
